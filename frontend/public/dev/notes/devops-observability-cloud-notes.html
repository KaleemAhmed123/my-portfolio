Containers

Docker fundamentals

A container packages app, runtime, dependencies, and config expectations.

Dockerfile

Use small base images, deterministic dependency install, non-root user, health checks, and multi-stage builds.

Images

Tag with commit SHA/version. Avoid :latest in production because rollback becomes ambiguous.

Containers

Ephemeral. Do not store uploads, sessions, or durable data inside the container filesystem.

Compose

Good for local multi-service development; production needs orchestration, restart policy, logs, secrets, and monitoring.

03
Proxy

Nginx reverse proxy and SSL

The gatekeeper in front of Node services.

Reverse Proxy

Receives public traffic and forwards to internal app ports. Hides backend topology from clients.

SSL Termination

Nginx handles HTTPS certificates and forwards to backend over internal HTTP or HTTPS depending on setup.

Headers

Set X-Forwarded-For, X-Real-IP, and X-Forwarded-Proto so app sees original client context.

Timeouts

Configure connect/read/send timeouts. Hanging backends should not consume proxy workers forever.

"Why does my app think all users have the same IP?"

"Because it is behind a reverse proxy and the app is reading the proxy IP. Nginx must forward the original IP using X-Forwarded-For/X-Real-IP, and the app must trust the proxy correctly. This matters for logging, rate limiting, geo checks, and security monitoring."

04
Delivery

GitHub Actions and deployment flow

Every deploy should be repeatable and reversible.
CI: install dependencies, lint, typecheck, test, build Docker image.
Secrets: injected from GitHub/AWS secret manager, never committed or baked into image.
Deploy: push image with commit tag, update ECS service or VPS container, wait for health checks.
Rollback: redeploy previous image tag or ECS task definition revision.
Migration: run DB migrations safely before/after app deploy depending on compatibility.

06
Runbooks

Production incident thinking

Interviewers look for calm, ordered debugging.

High latency

  • Check recent deploys
  • Inspect p99 by route
  • Look at DB slow queries and pool wait
  • Check queue/backpressure

5xx spike

  • Check app logs and Sentry
  • Check dependency health
  • Inspect ALB target health
  • Rollback if tied to release

Queue backlog

  • Producer rate vs consumer rate
  • Worker crashes
  • Poison messages
  • Scale consumers only if dependency can handle it

Deployment failure

  • Health check failing
  • Missing env var
  • Migration mismatch
  • Bad image or port config

DC
Docker

Docker in project and interview detail

Know what actually goes inside an image and what should never go inside.

Good Dockerfile principles

  • Install dependencies deterministically with lockfile.
  • Use multi-stage builds so final image contains only runtime artifacts.
  • Run as non-root user where possible.
  • Expose only the app port and use environment variables for config.
  • Do not copy .env, secrets, local uploads, or dev artifacts into the image.
  • Add health endpoint in the app; orchestration uses it to decide readiness.

Container lifecycle

Containers should be replaceable. Logs go to stdout/stderr, durable files go to object storage/volumes, config comes from env/secret manager, and multiple replicas should behave the same.

Production Dockerfile shape
FROM node:20-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci

FROM node:20-alpine AS build
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build

FROM node:20-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
USER node
EXPOSE 3000
CMD ["node", "dist/server.js"]
AWS
Cloud

AWS interview depth by service

Know service responsibilities and how requests flow through them.
Route 53 resolves api.example.com to an ALB DNS name. TTL controls DNS caching behavior.
ALB terminates HTTPS, applies listener rules, checks target health, and forwards requests to ECS tasks or EC2 instances.
ECS service keeps the desired number of tasks running and rolls out new task definitions during deploys.
Task role grants app permissions to AWS services like S3 or CloudWatch without hardcoded keys.
CloudWatch collects logs/metrics and triggers alarms. Prometheus/Grafana can provide app-level metrics and dashboards.
Common questionStrong answer
Security group vs NACLSecurity groups are stateful instance/resource firewalls. NACLs are stateless subnet-level rules. Most app-level access control uses security groups.
IAM user vs roleUsers are identities, usually for humans. Roles are assumed by services/workloads and are preferred for EC2/ECS because they avoid long-lived keys.
ALB vs NLBALB is layer 7 HTTP routing with host/path rules and TLS termination. NLB is layer 4 TCP/UDP and is faster/lower-level.
S3 public accessDefault should be private. Use pre-signed URLs, CloudFront, bucket policies, and least privilege.
ECS task vs serviceA task is a running container set. A service maintains desired count, deployment, health, and replacement.
NG
Nginx

Nginx, SSL, DNS, and reverse proxy details

Useful for VPS deployments and debugging real production issues.

Reverse proxy responsibilities

Terminate HTTPS, forward to local app ports, set original client headers, enforce upload limits, compress responses, serve static files, and route multiple domains/apps on one server.

SSL setup

Use Let's Encrypt/Certbot or managed certificates. Redirect HTTP to HTTPS. After confirming stability, enable HSTS carefully because it tells browsers to refuse HTTP for future requests.

Common 502 causes

Node process down, wrong upstream port, app bound to localhost/container mismatch, firewall/security group issue, proxy timeout, crashed deployment, or health check hitting wrong path.

Nginx reverse proxy essentials
server {
  listen 443 ssl;
  server_name api.example.com;

  ssl_certificate /etc/letsencrypt/live/api.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;

  client_max_body_size 20m;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 5s;
    proxy_read_timeout 30s;
  }
}
CI
CI/CD

Safe deployment pipeline

Automation is valuable only when it protects correctness.
Pull request runs lint, typecheck, unit tests, integration tests, and build. Broken checks block merge.
Main branch builds immutable Docker image tagged with commit SHA and pushes it to registry.
Deployment updates ECS service or VPS container using the new image and environment-specific secrets.
Health checks must pass before traffic shifts fully. If health checks fail, deployment stops or rolls back.
After deploy, monitor error rate, p95/p99 latency, CPU/memory, queue depth, and business metrics.
Migration deploy rule

Database migrations must be compatible with both old and new application versions during rolling deploys. Use expand/contract: add new column/table first, deploy dual-read/write code, backfill, switch reads, then drop old schema later.

"What is the difference between logs, metrics, and traces?"

Logs are discrete event records useful for debugging details. Metrics are numeric time-series useful for dashboards and alerts. Traces show one request across services and dependencies, useful for finding where time was spent. A mature system uses all three with a shared trace/request ID.

INC
Incidents

Incident response framework

Use this when asked how you debug production.
Triage impact: which users, which routes, severity, start time, and whether data correctness is affected.
Stabilize first: rollback bad deploy, disable feature flag, scale workers, pause queue, or fail closed for risky actions.
Diagnose with evidence: logs, metrics, traces, recent changes, dependency status, database health.
Recover and verify: confirm metrics return to normal and affected workflows complete correctly.
Postmortem: root cause, detection gap, prevention, owner, deadline, and tests/alerts to prevent recurrence.
