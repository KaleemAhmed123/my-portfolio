Core

Git Internals

Git is just a key-value data store.

The Object Model

Blob: The contents of a file.
Tree: A directory (contains pointers to blobs and other trees).
Commit: A snapshot containing a pointer to the top-level tree, author info, and a pointer to the parent commit(s).
Tag: A named pointer to a specific commit.

Refs and HEAD

A branch (like main) is just a named reference (ref) pointing to the latest commit. HEAD is a special pointer that tells Git what branch you are currently on. A "detached HEAD" means HEAD points directly to a commit hash instead of a branch name.

02
Workflows

Branching Strategies

How teams collaborate without destroying each other's work.

Trunk-Based Development

Everyone merges to main (trunk) frequently (at least daily). Feature branches are short-lived. Requires robust automated testing and Feature Flags to hide unfinished work in production. Standard for modern CI/CD.

Gitflow

Heavyweight process. Distinct branches for develop, feature/*, release/*, and hotfix/*. Good for strictly scheduled, versioned software releases, but slows down web deployment cadence.

Advanced Operations

When things go wrong.
CommandWhen to use it
git rebase -iInteractive rebase. Used to squash multiple messy commits into one clean commit before merging. Keeps history linear.
git cherry-pickCopy a specific commit from one branch and apply it to another (e.g., pulling a hotfix into an older release branch).
git bisectBinary search through history to find exactly which commit introduced a bug.
git reflogThe safety net. Keeps a log of every time HEAD moved. Can recover "lost" commits after a bad rebase.

Q&A

Interview Questions

Prove you can fix a mess.
"What is the difference between Rebase and Merge?"

"git merge creates a new 'merge commit' that ties two histories together, preserving the exact timeline but resulting in a messy, branching history graph. git rebase rewrites history by moving the base of your feature branch to the tip of the target branch, creating a clean, linear history. Rule of thumb: Rebase local, unpushed changes; Merge shared branches."

"How do you undo the last commit?"

"If I just want to change the message or add a file I forgot, I use git commit --amend. If I want to undo the commit entirely but keep the code changes, I use git reset --soft HEAD~1. If I want to nuke the commit and the code changes, I use git reset --hard HEAD~1. If the commit is already pushed and shared, I use git revert <commit-hash> to create a new commit that undoes the changes."
